# PhotoArchiver 用户使用手册

> **适用对象**：使用 Windows 安装包的最终用户。
> 源码形态（git clone + Python 环境）的开发者请参阅 [`docs/development/getting-started.md`](../development/getting-started.md)。
> 版本：适用于 v2.8.0 及以上。查看本机版本：启动后日志首行 `Starting PhotoArchiver v2.8.0`（日志位置见 §8）。

---

## 1. PhotoArchiver 是什么

一款**本地照片归档工具**：把照片文件夹导入本地库，用 AI 人脸识别把照片自动关联到人员，经人工审核后按 `{归档根目录}/{人员}/{日期}/{原文件名}` 的结构整理归档，并支持导出报告与重复检测。

**数据全部存放在您自己的电脑上**——不联网上传，无账号体系。唯一的联网动作是（在线版安装后）一次性下载人脸识别模型包，或使用"检查类"网络功能（当前版本无）。

## 2. 安装

### 2.1 两种安装包的区别

| 安装包 | 大小 | 内含识别模型 | 适用 |
|---|---|---|---|
| `PhotoArchiver-<版本>-setup.exe` | ~150MB | ❌ 需装后下载一次（约 300MB，需联网） | 网络通畅的日常安装 |
| `PhotoArchiver-<版本>-offline-setup.exe` | ~440MB | ✅ 已内置（构建期校验过） | 无网/内网/受限环境，或不想等下载 |

两者功能完全一致，可互相覆盖升级。均**免管理员权限**，安装到 `%LOCALAPPDATA%\Programs\PhotoArchiver`。

### 2.2 安装步骤

1. 从 [GitHub Releases](https://github.com/Rookievegetable/PhotoArchiver/releases) 下载安装包；
2. 双击运行（首次可能弹出 SmartScreen 提示——应用当前未做代码签名，点"更多信息 → 仍要运行"）；
3. 按向导完成安装，可选创建桌面快捷方式；
4. 安装完成后可直接勾选"启动"。

### 2.3 首次启动后的模型准备（仅在线版需要）

- **离线版**：模型已内置，跳过本节；
- **在线版**：识别功能需要模型包。打开安装目录（默认 `%LOCALAPPDATA%\Programs\PhotoArchiver`），运行 **`PhotoArchiver-cli.exe download-models`**——自动下载、sha256 校验、解压就绪（约 300MB，一次性）。模型就绪前其余功能（导入、扫描、审核、归档、导出、查重）均正常可用。

> 未签名应用的说明：SmartScreen/杀软可能拦截未签名程序，属预期；日志与数据库写入不受影响。

## 3. 首次使用前的两项配置

### 3.1 设置归档根目录（归档功能必填，一次性）

点击左侧导航的 **设置**，在 **归档根目录** 一栏选择或输入归档总目录（如 `D:\PhotoArchive`），保存。此后所有归档都整理到该目录下。

> 也可以不填这里，改在安装目录放 `.env` 文件写 `ARCHIVE_ROOT=<目录>`（高级用法）。两者都未配置时，点"归档"会给出明确提示。

### 3.2 调整识别灵敏度（可选）

设置中的 **匹配阈值**（默认 0.40）：调低 → 更容易判定为同一人（召回多、误配多）；调高 → 更严格。仅影响之后的识别，历史结果需重新识别。

## 4. 核心工作流（推荐首次按顺序走一遍）

主窗口左侧导航包含五项：**概览 / 照片库 / 审核中心 / 数据工具 / 设置**；窗口顶部工具栏常驻五个频繁主操作（自左向右即标准业务环节）：

```text
① 导入人员 → ② 扫描文件夹 → ③ 运行人脸识别 → ④ 审核待处理 → ⑤ 归档
     （导出数据 / 检测重复 / 删除人员 / 设置 在「数据工具」页与导航中；可用性见下）
```

界面采用统一视觉层级：主 CTA 为高亮主按钮，归档正式写入、移除登记、删除人员等不可逆操作统一为红色危险按钮并默认焦点在「取消」。面向验收人员的端到端人工验收脚本（含高 DPI/主题抽查与已知验证边界）见 [`../development/ui-acceptance-script.md`](../development/ui-acceptance-script.md)。

### 概览页（首次打开即见）

- 显示五步检查清单：**导入人员 → 扫描照片 → 运行人脸识别 → 人工审核 → 安全归档**，每一步标注 ✓ 已完成或 ○ 待办，并给出原因说明；
- 清单下方有**唯一的主按钮**指向当前最合理的下一步（如空库时为「导入人员」，缺人员但有照片时也是「导入人员」——识别需要两者齐全）；
- 允许先扫描再导入，主按钮会引导补齐缺失的一侧；
- 页面底部有隐私说明：所有照片与识别数据均保存在本机，处理全程离线完成，无需账号，不会自动上传任何文件。

### 当前任务与取消（v2.8.0 之后的源码更新，尚未发布安装包）

- **一个主窗口同时只运行一个冲突任务**：导入、扫描、识别、归档、导出互斥。从打开文件选择或预览对话框起即占用入口；关闭对话框且未提交时恢复。
- 任务运行时，审核待处理、检测重复（包含后续处置）、删除登记、删除人员、设置及已加载插件动作也暂不可用。禁用动作的提示说明正在进行的操作；上述同步操作的对话框打开期间也不允许启动冲突任务。
- 照片筛选、浏览和缩略图加载不受这条任务互斥规则限制。完成、失败或取消后，照片墙按**当前筛选条件**重新查询，已写入的部分结果不会因取消而回滚。
- 状态栏显示任务名称、进度消息；总数已知时显示百分比，未知时显示“总数未知”。
- **取消任务**仅对当前任务有效。点击后显示“正在请求取消；当前处理单元完成后停止，已完成部分会保留”，等待终态前不允许重复取消或启动其他冲突任务。取消为协作式任务边界检查（LIMIT-002），不保证立即或逐张停止；文件选择、同步操作及任务结束后不能用它取消。
- 若取消请求发送失败，界面会说明失败并允许重试；若结束后的页面刷新失败，会显示提示，任务入口仍恢复，原始任务错误不会被刷新错误遮住。

此规则只协调该主窗口的宿主入口，不是插件沙箱，也不锁定其他进程或 CLI；设置中的识别线程并发数仍然有效。现有 v2.8.0 安装包不包含这一未发布源码更新。

### ① 导入人员

工具栏 **导入人员**，选择名单文件（`.txt` / `.csv` / `.tsv` / `.xlsx` / `.xlsm` / `.xls`）。**导入分为两步：先解析成草稿供你核对，确认后才写入正式人员名单。**

**第一步：导入预览与确认对话框**

- 文件打开时自动识别**编码**（UTF-8 / 带 BOM / UTF-16 / GB18030）与**分隔符**（逗号 / 制表符 / 分号），顶部显示文件、编码、分隔符；可勾选或取消「首行为表头」、切换**工作表**后点「重新解析」重新生成草稿；
- 每行显示四类信息：**原始内容 / 解析结果（姓名 · 工号 · 部门 · 备注）/ 告警 / 处理动作**；
- 解析结果可直接双击修改；「处理动作」下拉可按行选择 **新建人员 / 合并到已有人员 / 跳过**；
- **告警默认给出建议动作，但不静默改写数据**：
  - 疑似**组标题**行（如「2组」「第 3 组」「名单」）提示并默认**跳过**，不会写成人员；
  - 单元格里用顿号、逗号、分号串联了多个姓名（如「1曹徽文、2曹紫夏」）时提示「可点击拆分」，点该行**拆分**按钮即按分隔符拆成多行（拆分是明确动作，不自动发生）；
  - **工号重复**（强冲突：名单内重复或与库内已有人员重复）默认**合并到已有人员**；**姓名+部门重复**（弱冲突）同样提示并默认合并；
  - 姓名为空的行提示并默认跳过。
- 底部实时显示 **「将新建 N · 合并 N · 跳过 N · 告警 N」**；名单超过 500 行时对话框内给出说明，确认后在后台执行并在状态栏显示结果。

**第二步：确认与结果**

- 点「**确认导入**」才写入正式人员名单，写入顺序与预览中的草稿顺序一致（该顺序即人员筛选下拉的展示顺序）；状态栏显示「导入完成：新建 N · 合并 N · 跳过 N」，个别行失败会带行号说明并只影响该行；
- 点「**取消**」不写任何正式人员；草稿会保留在库中（可回溯），随时可重新导入同一文件；
- 未提供证件号的行没有去重依据，重复导入会新增记录——**建议正式名单务必提供唯一证件号**。

> 本节描述的是 v2.8.0 之后的源码更新（人员导入两段式），现有 v2.8.0 安装包仍为「选文件后直接导入」的旧行为，安装包更新后以本节为准。

### ② 扫描文件夹

**扫描文件夹** → 选择照片目录 → 程序递归扫描并注册入库：

- 自动提取尺寸、拍摄时间（EXIF 优先）、内容 SHA-256 哈希；
- 进度实时显示在底部状态栏；完成后照片出现在中央照片墙；
- **重扫对账**：对同一目录再次扫描时，内容有变化的照片自动刷新登记，未变化的保持不动；新增的自动补齐；
- **照片墙角标**：每张照片右上角显示状态——`未匹配`（还没识别）/ `待审核` / `已通过` / `已拒绝`，已归档的追加 `· 已归档`；
- 照片墙支持按 **人员 / 状态（含"未匹配"）/ 拍摄时间** 组合筛选；时间默认为 **全部时间**，选 **自定义时间** 才展开起止日期；开始时间晚于结束时间时查询被阻止并显示内联修正提示（不会静默显示空结果）；
- 筛选栏下方始终显示 **已生效条件摘要** 与 **结果计数**，点 **清除筛选** 一键复位；
- 大库首次枚举会有短暂加载。照片墙的空态分三种，不会混淆：**库中还没有照片**（给「扫描照片」按钮）、**筛选无结果**（给「清除筛选」按钮）、**任务进行中**（显示等待说明，完成后自动刷新）；
- **双击照片** 打开只读详情：较大预览、原始文件名/路径、拍摄时间与当前状态（数据缺失时如实显示"未知"，缩略图未生成时给出提示）；
- **选中照片**（多选）时出现上下文批量操作栏：**归档所选（N）** 与 **移除登记（N）**，按钮上明确显示选中数量；未选中时该栏整体隐藏，任务进行中两个按钮均置灰。

### ③ 运行人脸识别

**运行人脸识别** → 后台对"还没有识别结果的照片"执行检测/匹配（自动续跑，不会重复识别已处理的）。

- 功能尚不可用时按钮**直接置灰并说明原因**：未导入人员、未登记照片、照片均已有识别结果、或识别模型未就绪——无需点击后才发现；
- 缺人员/缺照片/全部已识别时，工具栏下方出现**下一步按钮**（如「识别下一步：导入人员」「前往审核待处理」），点击直达对应功能；缺模型时给出模型安装说明（见 §2 在线版 download-models）；
- 结果分为：匹配到人员（进入待审核）、未匹配到已知人员、无人脸；均可在照片墙角标与 **审核待处理** 中查看；
- 取消：过程中点 **取消任务** 可协作中止（已完成的部分保留，续跑接续）。

### ④ 审核待处理

**审核待处理**（工具栏）或左侧导航 **审核中心** 打开审核对话框。每条记录一行，显示**照片缩略图**、**文件名**、**候选人员**、**置信度**（文字分级如「较高」，括号内保留精确数值 0.87 供审计）与**状态**；对话框顶部常驻**待审核总数**：

- 勾选若干条（支持 Ctrl/Shift 键盘多选）→ **通过所选（N）** / **拒绝所选（N）**，按钮上明确显示选中数量；**全部通过（N）** 会先弹出确认框，明确数量并说明界面内没有批量撤销，取消（默认）不改任何数据；
- 暂无待审核结果时对话框**保持打开**并显示空态说明，不会一闪而过；此时操作按钮置灰，审核完成后刷新立即生效；
- 只有 **已通过** 的照片才会进入归档；
- 审核即时生效持久化，可随时关闭稍后继续；
- 审核后照片墙角标与概览计数实时更新（回到 `未匹配` 筛选可找出漏网照片）。

### ⑤ 归档

**归档** 打开归档预览：

1. 预览首行声明本次**范围**（「已选 N 张照片」或「全部已通过照片」），并列出计划/跳过数量与按人员分组明细；
2. 预览附**源 → 目标示例**（前 8 项），明确每个文件将落到 `{归档根目录}/{人员}/{日期}/{原文件名}` 的哪个位置；
3. 冲突策略三选一（**跳过，默认** / **覆盖同名文件** / **自动重命名**），选择器下方以文字说明所选策略的后果；
4. **试运行默认勾选**——首次使用只看计划不动磁盘；确认按钮会如实显示当前模式：「执行试运行」或「开始归档」，切换到正式写入时默认焦点移到「取消」，误按回车不会写盘；
5. 点确认后执行，进度在状态栏；完成即完成文件复制 + 归档记录登记。

> 提示「未配置归档根目录」→ 可在弹出的询问中点「去设置」直达设置页；提示部分失败 → 逐项错误在日志中（见 §8），常见为源文件被移动/占用。
> 归档尚不可用时按钮置灰并说明原因：根目录未配置/不可用 → 下一步按钮直达**设置**；暂无可归档照片 → 直达**审核待处理**。

### ⑤·附 删除登记与取消

- **删除登记**（照片墙多选后）：把照片从**库内登记**中移除。预览对话框明确展示级联影响（识别结果、归档记录一并移除）——**磁盘上的照片文件永远不碰**。未选中任何照片时该入口不出现（批量操作栏隐藏）。

### ⑥ 导出数据

左侧导航 **数据工具** → **导出数据** → 选择范围（全部 / 按当前筛选）与格式（Excel / CSV / HTML 按扩展名自动识别）→ 生成报告。

- 选「按当前筛选」时对话框会显示**当前筛选条件摘要与预计导出数量**，与照片库一致；
- 「当前批次」范围未实现，已按产品决定从界面移除（不以不可选项形式出现）；
- 删除登记 / 删除人员等破坏性确认对话框默认焦点在「取消」，并明示界面内没有撤销操作。

## 5. 库管理（长期运营）

库管理操作集中在左侧导航的 **数据工具** 页（删除登记仍在照片库页、且需先选中照片）。

### 5.1 删除登记

**删除登记**（照片墙多选后）：把照片从**库内登记**中移除。预览对话框明确展示级联影响（识别结果、归档记录一并移除）——**磁盘上的照片文件永远不碰**。

### 5.2 删除人员

**删除人员**：下拉选择人员 → 预览级联（人脸特征删除、其识别结果转为"未知人员"、照片与归档保留）→ 确认执行。同样只动库，不动磁盘。

### 5.3 重复检测与处置

**检测重复** → 按内容哈希分组展示 → 可 **按建议处置**（每组保留最早登记的一张，其余移除登记）。预览确认后才执行。

## 6. 设置详解

| 设置项 | 说明 |
|---|---|
| 主题 | system / light / dark（跟随系统为默认） |
| 语言 | 占位项（界面当前为中文；切换暂未实装，见提示说明） |
| 默认导入目录 / 默认导出目录 | 打开文件对话框时的起始位置 |
| **归档根目录** | 归档总目录（§3.1）；此处设置优先于 `.env` |
| 匹配阈值 | 0–1，默认 0.40 |
| 最大并发数 | 后台识别的线程并发（默认 4） |

## 7. 命令行参考（`PhotoArchiver-cli.exe`）

位于安装目录。适合批量/无人值守场景，与界面同一处理管线。在安装目录下打开命令行运行，或使用完整路径。

| 命令 | 用途 |
|---|---|
| `PhotoArchiver-cli.exe scan <照片目录>` | 扫描注册（`--no-recursive` 仅扫一层，`--name` 显示名） |
| `PhotoArchiver-cli.exe import-people <人员文件>` | 导入人员（`--no-header` / `--sheet-name`）。CLI 为直通导入，不弹预览与确认对话框 |
| `PhotoArchiver-cli.exe recognize` | 人脸识别（默认续跑未识别的；`--all` 全量、`--limit N` 限量） |
| `PhotoArchiver-cli.exe download-models` | 下载/校验识别模型包（在线版首次使用） |
| `PhotoArchiver-cli.exe archive --archive-root <目录>` | 归档全部已通过照片（`--dry-run` / `--conflict-strategy`） |
| `PhotoArchiver-cli.exe export <输出文件>` | 导出（`--scope filtered` + `--status/--person/--captured-from/--captured-to`） |
| `PhotoArchiver-cli.exe prune-missing` | 清理磁盘上已失联的照片登记（默认 dry-run） |
| `PhotoArchiver-cli.exe backfill-content-hash` / `backfill-capture-time` | 历史数据一次性补齐（幂等） |
| `PhotoArchiver-cli.exe cleanup-thumbnails` | 清理缩略图缓存孤儿（默认 dry-run） |
| `PhotoArchiver-cli.exe migrate` | 旧版数据库迁移到用户数据目录（默认 dry-run） |

所有写库命令启动时都会自动生成数据库快照备份；`--dry-run`/预览类命令不写库不落盘。

## 8. 数据位置 · 备份 · 升级

### 8.1 数据都在哪里

| 内容 | 位置 |
|---|---|
| 业务数据库（单文件 SQLite，含人员/照片/审核/归档记录） | `%LOCALAPPDATA%\PhotoArchiver\photo_archiver.db` |
| 自动备份 | 同目录 `backups\`，滚动保留最近 3 份（每次启动生成） |
| 运行日志 | `%LOCALAPPDATA%\PhotoArchiver\Logs\photo_archiver.log`（10MB 轮转 × 30 天） |
| 识别模型 | `<安装目录>\models\buffalo_l\` |
| 缩略图缓存 / 导出产物 | 输出目录下（设置中的默认导出目录） |

### 8.2 备份

停止程序后**拷贝单个数据库文件**即完成完整备份（人员、照片、审核、归档全部在内）。程序自身每次启动也自动做一致性快照。缩略图与导出产物为派生数据，可随时重建。

### 8.3 升级

下载新版本安装包直接覆盖安装：用户数据库、偏好、模型自动保留；新版本的数据库结构变更在首次启动时自动完成；升级前程序会自动生成一份启动备份。升级后首次启动建议看一眼日志首行确认版本号。

### 8.4 卸载

控制面板卸载只移除程序本身；**数据库与日志保留**在用户目录（如需彻底清除请手动删除 `%LOCALAPPDATA%\PhotoArchiver`，注意其中包含数据库——删除前务必备份）。安装目录下的识别模型会随卸载移除，重装后用 `download-models` 恢复或用离线安装包重装。

## 9. 常见问题（速查）

| 现象 | 处理 |
|---|---|
| 识别提示"model pack not found" | 在线版：运行 `PhotoArchiver-cli.exe download-models`；离线版：重新覆盖安装 offline 安装包 |
| 点"归档"提示未配置归档根目录 | 设置 → 归档根目录 填一次；或见 §3.1 |
| 识别结果不准 | 设置中调匹配阈值（低=宽松，高=严格），改后重新识别 |
| 扫描时短暂卡顿 | 大库目录枚举在界面线程完成（约 70µs/张），属预期 |
| macOS 上扫描偶发崩溃 | macOS 为实验性支持；重试即可，数据有备份兜底（详见 FAQ 已知问题节） |
| 安装时 SmartScreen 警告 | 未签名应用预期行为："更多信息 → 仍要运行" |
| 程序行为异常想反馈 | 附上 `%LOCALAPPDATA%\PhotoArchiver\Logs\` 最近日志（注意去除隐私路径）；日志首行含版本号 |

完整 FAQ 与 macOS 已知问题详见 [`faq.md`](faq.md)。

## 10. 已知限制（诚实声明）

- **macOS 为实验性支持**：存在与运行环境相关的概率性扫描崩溃（第三方库线程缺陷），已如实披露；Windows/Linux 不受影响；
- 识别模型的首次获取依赖 GitHub 可达（离线安装包用户不受影响）；
- InsightFace 模型在部分平台需要编译安装（源码形态）；安装包形态已内置无需编译；
- "当前批次"导出未实现且已从界面移除（导出提供全部/按当前筛选两种范围）；未来如需恢复将随批次持久化设计一并交付；
- 大照片库（10 万张级）扫描开始时的目录枚举会短暂占用界面。
