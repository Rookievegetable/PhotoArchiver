# PhotoArchiver · 人员名单导入阶段 A 桌面验收脚本

> 适用构建：阶段 A 源码构建（含 migration `003_import_batches_and_roster`；v2.8.0 安装包不含本功能）。
> 目标：按本脚本逐步操作即可覆盖阶段 A 的五个验收点——①预览四区与计数；②多人拆分；③组标题/重复默认动作；④取消保留草稿；⑤确认后 roster 顺序——外加编码/分隔符/工作表/格式边界与 >500 行后台确认。
> 每条「预期」均已由**真实 `ParseImportDraftService` + 真实 SQLite 全序列探测**实测（探测脚本 `logs\probe_full_sequence.py`，输出 `logs\probe_full_sequence.txt`），不是估算；§10 登记了探测中发现、需 owner 裁决的两个行为。

## 0. 环境准备（1 分钟）

验收工具包已在桌面：`PhotoArchiver-阶段A验收\`

```
启动验收环境.cmd            ← 双击启动（专用库，不影响日常库与 v2.8.0 安装版）
名单样本\                   ← 7 个样本文件（01–07，按场景预置）
make_samples.py             ← 样本生成 + 期望值探测脚本（重跑可重建样本）
```

- 专用库：工具包 `data\stage_a_acceptance.db`（首次启动自动建表到迁移 003）；**清空重验**：删除该文件即可。
- **顺序重要**：§1→§8 按序执行——§4 的预期依赖 §1/§3 已写入的人员。

**预期启动**：窗口落在「概览」页；检查清单第 1 步「导入人员」为 ○；主按钮为「导入人员」。

## 1. 正常名单（baseline）

工具栏「导入人员」→ 选 `名单样本\01_正常_逗号_UTF8.csv`。

- **预期**：弹出「导入预览与确认」；顶部显示 `文件：01_正常_逗号_UTF8.csv 编码：auto 分隔符：,`；「首行为表头」已勾选；表头列 = 姓名/工号/部门/备注。
- **预期**：3 行全部「新建人员」，无告警；底部计数 **「将新建 3 · 合并 0 · 跳过 0 · 告警 0」**；不出现大名单提示行。
- 点「确认导入」。**预期**：状态栏 **「导入完成：新建 3 · 合并 0 · 跳过 0」**；概览第 1 步变 ✓；照片库人员下拉依次为 **张三 → 李四 → 王五**（roster 顺序）。

## 2. 取消保留草稿（验收点④）

「导入人员」→ 选 `02_中文编码GB18030_组标题_多人串联.csv`（GB18030 编码，验收中文不乱码）。

- **预期**：3 行——
  - 「1曹徽文、2曹紫夏、3贾偌涵」→ **新建人员**，告警「该单元格疑似包含 3 个姓名，可点击「拆分」」，行尾有**拆分**按钮；
  - 「2组」→ **跳过**，告警「疑似组标题（2组），默认跳过，不作为人员写入」；
  - 「李梅 / GH010」→ 新建，无告警。
- **预期计数**：**「将新建 2 · 合并 0 · 跳过 1 · 告警 2」**。
- 直接点「取消」。**预期**：状态栏 **「已解析 3 行草稿，请在预览中确认。」**；人员下拉**仍是张三/李四/王五 3 人**（未写入）；再次选同一文件可重新打开预览（草稿留痕供回溯）。

## 3. 多人拆分（验收点②）

再次选 `02` 样本 → 第 1 行点「**拆分**」。

- **预期**：立即拆为 3 行「1曹徽文 / 2曹紫夏 / 3贾偌涵」，拆分按钮随之消失；「2组」行保持跳过；计数变为 **「将新建 4 · 合并 0 · 跳过 1 · 告警 1」**。
- 点「确认导入」。**预期**：状态栏「导入完成：新建 4 · 合并 0 · 跳过 1」；人员下拉为 **张三、1曹徽文、李四、2曹紫夏、王五、3贾偌涵、李梅**——两个批次在此**交错排列**（并列序位按创建时间排列，单批次内相对顺序不变；见 §10 发现 F-A1，待裁决）。

## 4. 组标题与重复默认动作（验收点③）

选 `03_重复_强弱冲突.csv`（此时库内已有张三/GH001、王五/GH003）。

- **预期**：4 行**全部**「合并到已有人员」，计数 **「将新建 0 · 合并 4 · 跳过 0 · 告警 4」**：
  - 第 1 行 张三/GH001：告警「工号与库内已有人员重复（强冲突）」；
  - 第 2 行 张三/GH001：三条告警——「工号在名单内重复（强冲突）：GH001」「工号与库内已有人员重复（强冲突）」「姓名+部门在名单内重复（弱冲突）」——**动作仍为合并**（库内重复覆盖了文件内重复的"跳过"，见 §10 发现 F-A2）；
  - 第 3 行 王五/GH003：告警「工号与库内已有人员重复（强冲突）」；
  - 第 4 行 王五/GH004：告警「姓名+部门在名单内重复（弱冲突）」+「姓名+部门与库内已有人员重复（弱冲突）」。
- 点「确认导入」。**预期**：「导入完成：新建 0 · 合并 4 · 跳过 0」；人员总数**不变**（仍是 7 人），不产生重复人员。
- 对照（可选）：在空库导入同一样本，预期为 **「将新建 3 · 合并 0 · 跳过 1 · 告警 2」**（第 2 行按"文件内重复"跳过，第 4 行弱冲突仅提示仍新建）。

## 5. 编码与分隔符边界

选 `06_无表头_分号_UTF16.txt`（UTF-16 + 分号分隔 + 无表头）。

- **预期（默认勾选"首行为表头"）**：分隔符 `;`；只有 **1 行**「钱二」，工号/部门为空——首行「赵一」被当表头消耗，取消勾选「首行为表头」→ 点「**重新解析**」后出现 2 行（赵一/GH300/技术部、钱二/GH301/市场部）。
- 确认导入后：状态栏「导入完成：新建 2 · 合并 0 · 跳过 0」。
- 对 `01` 样本不改任何选项再点一次「重新解析」：**预期**计数与首次解析一致（幂等，无副作用）。

## 6. 旧格式 .xls（D1 决策落地）

选 `04_旧格式_xls.xls`。

- **预期**：正常弹出预览，2 行全部新建（**王小明 / W001 / 档案室、李小红 / W002 / 办公室**）；编码与分隔符栏显示 `—`；确认后正常落库。

## 7. 工作表切换（多 sheet）

选 `05_双工作表.xlsx`。

- **预期**：出现「工作表」下拉，含「第一组 / 第二组」；默认「第一组」= 2 行（陈某/GH100、林某/GH101）。点「确认导入」先写第一组。
- 再次选同一文件 → 切到「**第二组**」→「重新解析」：**预期**只剩 1 行「黄某 / GH200 / 市场部」，计数「将新建 1 · 合并 0 · 跳过 0 · 告警 0」；确认后落库。

## 8. 大名单后台确认（>500 行）

选 `07_大名单_501行.csv`。

- **预期**：预览计数区上方出现一行说明 **「名单超过 500 行，确认将在后台执行，完成后状态栏显示结果。」**（≤500 行时不出现）；计数「将新建 501 · 合并 0 · 跳过 0 · 告警 0」。
- 点「确认导入」。**预期**：状态栏先显示「导入确认已提交后台执行，完成后显示结果。」，随后转 **「导入确认完成」**；确认期间导入/扫描/识别等冲突入口置灰；完成后人员下拉共 **515 人**，末位为「人员0501」。

## 9. 确认后 roster 顺序（验收点⑤ 总核验）

完成 §1–§8 后人员下拉共 515 人。**实测最终顺序**（前 14 项 + 末尾 3 项，与全序列探测输出逐行一致）：

```
 0. 1曹徽文        ← 批次 02 序位 1
 1. 赵一           ← 批次 06 序位 1
 2. 王小明         ← 批次 04 序位 1
 3. 陈某           ← 批次 05 序位 1
 4. 黄某           ← 批次 05 序位 1（第二组）
 5. 人员0001       ← 批次 07 序位 1
 6. 张三           ← 序位 2（批次 01 原序位 1，经 §4 合并重写为 2）
 7. 李四
 8. 2曹紫夏
 9. 钱二
10. 李小红
11. 林某
12. 人员0002
13. 3贾偌涵
...
512. 人员0499
513. 人员0500
514. 人员0501
```

**单批次内**的顺序承诺（验收点⑤的实质）已满足：同一次导入确认的人员按草稿顺序排列（见 §8 大名单连续段 `人员0001…0501`）。**跨批次**因并列序位按创建时间交错——符合方案 A-1「唯一性不强制，允许并列」的字面约定，是否符合"稳定名单顺序"的直觉需 owner 裁决（见 §10 F-A1）。

## 10. 验收发现（探测阶段登记，待 owner 裁决）

| ID | 发现 | 实测证据 | 建议裁决选项 |
|---|---|---|---|
| F-A1 | **跨批次 roster 顺序交错**：每批 `order_seq` 从 1 起编，`roster_order` 并列时按创建时间/姓名交错（§3/§9 可见） | `logs\probe_full_sequence.txt` 最终顺序；`test_import_draft_flow.py::test_confirm_writes_people_with_roster_order` 锁定单批次内顺序 | ① 接受现状（方案 A-1 字面）；② 确认时从 `max(既有 roster_order)+1` 起编（跨批次单调递增）；③ 推迟到 F 阶段历史回填统一裁决 |
| F-A2 | **强冲突优先级**：文件内重复（默认跳过）与库内重复（默认合并）同时命中同一行时，库内重复的"合并"覆盖"跳过"（§4 第 2 行实测） | `logs\probe_section4.txt` 第 2 行三告警 + merge_existing | ① 接受现状（库内优先）；② 文件内重复优先跳过；③ 两类同时命中时单列动作或要求人工选择 |
