# PhotoArchiver · 人员名单导入阶段 A 桌面验收脚本

> 适用构建：阶段 A 源码构建（含 migration `003_import_batches_and_roster`；v2.8.0 安装包不含本功能）。
> 目标：按本脚本逐步操作即可覆盖阶段 A 的五个验收点——①预览四区与计数；②多人拆分；③组标题/重复默认动作；④取消保留草稿；⑤确认后 roster 顺序——外加编码/分隔符/工作表/格式边界与 >500 行后台确认。
> 每条「预期」均已由**真实 `ParseImportDraftService` + 真实 SQLite 全序列探测**实测（探测脚本 `logs\probe_full_sequence.py`，输出 `logs\probe_full_sequence.txt`），不是估算；§10 登记了探测中发现、需 owner 裁决的两个行为。

## 9. 确认后 roster 顺序（验收点⑤ 总核验）

完成 §1–§8 后人员下拉共 515 人。**实测最终顺序**（裁决实施后全序列探测，前 14 项 + 末尾 3 项）：

```
 0. 李四       roster=2   ← 批次 01（张三/王五经 §4 合并被重写序位，见下）
 1. 1曹徽文    roster=4   ← 批次 02（基线=3，从 4 续编）
 2. 2曹紫夏    roster=5
 3. 3贾偌涵    roster=6
 4. 李梅       roster=8   ← 「2组」占序位 7（跳过留空位）
 5. 张三       roster=9   ← 批次 03 合并重写（§4 第 1 行序位 9）
 6. 王五       roster=12  ← 批次 03 合并重写（§4 第 3/4 行序位 11/12）
 7. 赵一       roster=13  ← 批次 06
 8. 钱二       roster=14
 9. 王小明     roster=15  ← 批次 04
10. 李小红     roster=16
11. 陈某       roster=17  ← 批次 05 第一组
12. 林某       roster=18
13. 黄某       roster=19  ← 批次 05 第二组
...
512. 人员0499  roster=518
513. 人员0500  roster=519
514. 人员0501  roster=520  ← 批次 07 连续段，无交错
```

**两项裁决落地后的顺序语义**（验收点⑤ 汇总）：

1. **全局单调（F-A1）**：每批从 `max(既有 roster_order)+1` 续编，任何批次之间不再交错；单批次内顺序 = 草稿顺序（跳过行留空位）。
2. **合并重写序位**：`merge_existing` 会把既有人员的 `roster_order` 重写到本批次的序位（如 §4 把张三重写到 9、王五重写到 12）——合并即"把该人排到本批名单的这个位置"，属阶段 A 语义；批量重排入口在阶段 B（人员管理页）落地。
3. **文件内重复优先跳过（F-A2）**：同文件重复行不再被库内合并覆盖。
