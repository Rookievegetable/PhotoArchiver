# PhotoArchiver 桌面 GUI 人工验收脚本（UI/UX Batch 7 交付）

> 适用版本：包含 UI/UX Batch 1–7 的构建（源码运行或安装包均可）。
> 目标：非开发者按本脚本逐步操作，即可验证核心流程与 Batch 1–7 的全部交互承诺。
> 每个步骤的「预期」全部来自已提交的自动化测试所锁定的行为；人工执行用于覆盖
> 自动化无法验证的部分：真实高 DPI 缩放、真实主题、真实工作线程与磁盘写入。
>
> 完成后请在验收记录中勾选各项并注明环境（Windows 版本 / 缩放比例 / 主题）。

## 0. 环境准备

| 项 | 要求 |
|---|---|
| 操作系统 | Windows 10/11（macOS 为实验性支持，见 §9 边界） |
| 缩放 | 依次在 100%、125%、150% 下执行 §1 空库首用与 §6 归档确认两项抽查 |
| 主题 | 浅色与深色（Windows 设置 → 个性化 → 颜色）各执行一遍 §1 与 §6 |
| 数据 | 一个临时照片目录（10–50 张含人像照片）、一个人员名单 Excel |

## 1. 空库首次使用（Batch 3 概览 + Batch 4 空态）

1. 首次启动（或使用全新库目录）。
2. **预期**：默认落在「概览」页；五步检查清单显示"导入人员 → 扫描照片 → 运行人脸识别 → 人工审核 → 安全归档"，唯一主按钮（蓝色高亮）指向「导入人员」；底部显示本地处理/不上传说明。
3. 切到「照片库」页。
4. **预期**：空态卡片显示"库中还没有照片"与「扫描照片」按钮；不出现"筛选无结果"文案，也不出现任何批量操作按钮。

## 2. 导入人员（Batch 2 就绪状态）

1. 概览页主按钮「导入人员」→ 选择人员 Excel。
2. **预期**：完成后检查清单"导入人员"一步变为 ✓；主按钮自动切换为「扫描照片」。
3. 此时直接点「运行人脸识别」。
4. **预期**：按钮置灰，提示缺照片，且给出可点击的「下一步」直达扫描。

## 3. 扫描 → 识别（Batch 1 任务协调）

1. 扫描照片目录；进度实时显示在底部状态栏。
2. **预期**：扫描运行期间，「导入/识别/归档/导出/审核/设置」等冲突入口置灰且 tooltip 说明原因；「取消任务」按钮在状态栏可见。
3. 扫描完成后运行人脸识别；中途点「取消任务」。
4. **预期**：状态栏显示"正在请求取消；当前处理单元完成后停止"类文案，已完成部分保留；任务结束后按钮恢复，概览计数与照片库照片同步出现。

## 4. 审核中心（Batch 5）

1. 照片库中确认每张照片右上角有**文字**角标（`未匹配`/`待审核`/`已通过`/`已拒绝`），不是仅颜色区分。
2. 打开「审核中心」。
3. **预期**：顶部显示"待审核 N 条"；每条记录两行：文件名+人员名 / 置信度文字分级（如"置信度：较高（0.87）"）+ 状态；有缩略图的记录显示小图。
4. 选中 2 条：**预期**按钮变为「通过所选（2）/ 拒绝所选（2）」。
5. 点「全部通过（N）」：**预期**弹出确认框，写明数量并说明界面内没有批量撤销，默认按钮为"否"——直接回车应无任何数据变化；点"是"后列表清空且对话框保持打开显示空态。
6. 关闭对话框后回到照片库：**预期**角标已变为「已通过」，无需手动刷新。

## 5. 筛选与空态区分（Batch 4）

1. 筛选栏选择"全部时间"→ 不出现起止日期；切换"自定义时间"→ 起止出现。
2. 把开始时间设得晚于结束时间。
3. **预期**：筛选暂停，显示内联修正提示；不显示空结果列表。
4. 修正后筛选一个必然无结果的组合（如某人员 + 未匹配）。
5. **预期**：空态显示"没有照片符合当前筛选条件"与「清除筛选」按钮（而不是"请扫描照片"）；筛选栏上方显示已生效条件摘要与结果计数。
6. 选中若干照片：**预期**出现「归档所选（N）/ 移除登记（N）」，数量与选中数一致；取消选中后整栏消失。

## 6. 归档安全表达（Batch 6 + owner 决策）

1. 选中若干已通过照片，点「归档所选（N）」。
2. **预期**：预览首行明确"已选 N 张照片"；列出计划/跳过数量、按人员分组、前 8 条"源 → 目标"示例；冲突策略下方有后果说明文字。
3. **预期**：试运行默认勾选，确认按钮显示「执行试运行」。
4. 取消勾选试运行：**预期**按钮变为「开始归档」（红色危险样式），且默认焦点移到「取消」——直接回车不会写盘。
5. 先执行一次试运行：**预期**结束后照片仍在库中、磁盘无新文件；再正式执行：完成后文件按 `{归档根}/{人员}/{日期}/{原文件名}` 落盘，照片角标追加「已归档」。
6. 临时清空归档根目录设置后再次点「归档」：**预期**询问"是否现在打开设置"，点「去设置」直达设置页。

## 7. 筛选导出（Batch 6）

1. 数据工具 → 导出数据，选"按当前筛选"。
2. **预期**：对话框显示当前筛选条件摘要与预计导出数量，且范围列表中**不存在**"当前批次"选项（未实现能力不以禁用项形式出现）。
3. 全部 / 按当前筛选各导出一次，核对文件行数与预期数量一致。

## 8. 危险操作确认（Batch 6）

1. 照片库多选 → 移除登记。
2. **预期**：确认框显示级联数量、"磁盘上的照片文件永远不碰"与"界面内没有撤销操作"明示；默认焦点在「取消」——直接回车不删除。
3. 数据工具 → 删除人员：同样默认焦点在「取消」，按钮为红色危险样式；取消后无任何变化。
4. 数据工具 → 检测重复：只读报告，无确认即无写入。

## 9. 验证边界（已知限制，如实披露）

以下各项**不属于**本脚本可验证范围，源于已登记的设计/平台限制（`KNOWN_ISSUES.md`）：

| 限制 | 边界 |
|---|---|
| LIMIT-001 | 真实"缺模型包 → 友好失败"完整链路依赖缺模型环境，CI 未覆盖；人工可在改名模型目录后启动识别观察失败提示，但结果不计入验收门。 |
| LIMIT-002 | 取消为任务边界粒度——大库扫描/识别时"取消"并非逐张即时停止，属设计特征；§3 的预期已按此措辞。 |
| LIMIT-004 | 本地按特定顺序单独运行部分测试子集可能触发 Qt 原生级崩溃/挂起；仅影响开发者调试，不影响本人工脚本。 |
| LIMIT-006 | macOS runner 环境漂移 SIGSEGV 已定性为第三方缺陷；macOS 上执行本脚本的第 3 步（扫描/识别）可能复现概率性崩溃——macOS 验收仅抽查其余步骤并如实记录。 |
