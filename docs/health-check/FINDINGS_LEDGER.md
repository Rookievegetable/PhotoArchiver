# FINDINGS_LEDGER.md — 全面工程健康审计 · 统一问题台账

- **建立**: 2026-09-28（Stage 0）
- **维护规则**: 每阶段结束时追加/更新；同一根因归并为一条（Root Cause → Affected → Symptoms），禁止机械拆分；后续阶段发现与既有条目同源时标记 DUPLICATE 并挂入 Evidence。
- **状态权威规则（Owner 决策 `FINDINGS-STATUS-AUTHORITY-APPROVED`，2026-10-11）**: 主表 **`Status` 字段唯一表示该 Finding 的当前处置状态**；标题/正文/Evidence 及 PROJECT_STATUS、历史报告中的 FIXED/RESOLVED/CLOSED 标记均为**历史处置记录或支持证据**，不构成第二个当前状态源；标题与 Status 不一致时以经证据核定后的 Status 为准。**每次 Status 变更必须有针对该 Finding 的可追溯证据**（禁止仅凭标题标记、臆测或未核实摘要改状态）；证据不足时置 `NEEDS-VERIFICATION` 并注明缺失证据与补证需求。
- **状态词汇**: `OPEN`（仍需处置，有证据支持未解决）/ `NEEDS-VERIFICATION`（处置状态无法可靠判定，须注明缺口）/ `FIXED`（修复或处置已充分验证）/ `ACCEPTED-RISK`（Owner 明确接受）/ `WONT-FIX`（Owner 决策不予修复）/ `DUPLICATE`（已归并，须注明目标 ID）。历史值 `CONFIRMED` 表示「问题已证实」而非处置状态（保留于正文/Evidence，不再是规范 Status 值）；`CLOSED` 不是独立规范值，按关闭原因归入 FIXED/ACCEPTED-RISK/WONT-FIX/DUPLICATE。
- **严重级别**: P0 数据损坏/安全/不可恢复 ｜ P1 核心业务错误/关键状态机/关键架构违约 ｜ P2 稳定性/维护成本/技术债 ｜ P3 文档缺陷/小型设计/可维护性
- **性质标注**: 每条注明 VERIFIED（本轮直接取证）/ NEEDS-VERIFICATION（待后续阶段复核）
